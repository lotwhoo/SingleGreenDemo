# M6 Stage 2A 任务记录：VAD 门控 ASR 集成

## 目标与边界

Stage 2A 将 M6 Stage 1 的无框架 VAD 契约接入 `VoiceChatCore` 的音频帧源、ASR 门控会话、`SingleGreenGlassesKit` 的 provider-neutral port 和 `SingleGreenDemo` 的适配器/设置页。它验证了编排边界与 fail-closed 行为，不宣称生产 VAD 检测器已经可用。

本阶段不包含 WebRTC 源码、预编译二进制、能量检测器生产回退、真实麦克风验收、真实 ASR/LLM/Search 服务或真机安装/启动。

## 已交付的公共边界

- `VoiceActivityDetectionKit` 保持 framework-neutral，负责 `VADPCMFrame`、检测器 actor port、确定性分段和 generation/cancellation 语义。
- `VoiceChatCore` 负责 `AudioCapture` 到 20ms 帧的转换、source/pending-upload 有界队列和 `VoiceActivatedASRSession`。ASR transport 在本地起音被确认前保持关闭。
- `SingleGreenGlassesKit` 只依赖 `VoiceActivatedSpeechRecognitionSession` 与结构化 `SpeechRecognitionFailure`；Controller 不依赖 AVFoundation、WebRTC 或供应商类型。
- `SingleGreenDemo` 只负责 live adapter、设置可用性和 composition。生产 detector factory 为空时，voice-activated 设置不可用并 fail closed；不会偷偷回退到旧的 amplitude timer 或 benchmark energy detector。
- 手动 PTT 路径仍然可用，作为当前兼容输入方式。

## 当前策略契约

所有数字以 20ms、16kHz、mono、Int16LE 帧为单位：

| 策略 | 值 | 语义 |
| --- | ---: | --- |
| 帧 | 20ms / 320 samples / 640 bytes | VAD 与 source 的固定输入 |
| pre-roll | 15 帧 / 300ms | 起音确认后保留前置音频 |
| onset | 3 / 5 帧 | 5 帧窗口内至少 3 个 speech 才确认起音 |
| 尾部静音 | 40 帧 / 800ms | speech 后结束 utterance |
| 最长段 | 1,000 帧 / 20s | 单段硬上限 |
| 无起音超时 | 750 帧 / 15s | armed 后没有起音则结束 |
| pending upload | 250 帧 | 上传积压有界；超限 fail closed |
| upload batch | 10 帧 / 200ms | ASR 上传批次上限 |

## 迁移与兼容说明

- `ASRFailure` 现在承载 typed failure payload；依赖方从无结构错误迁移到 `ASRFailure.Code` 是有意的本地 Package source migration。
- `AudioCapture.CaptureError.engineFailed` 现在是无 payload 的稳定错误；调用方不应读取或传播动态引擎描述，这是有意的本地 Package source migration，用于隐私安全和稳定分类。
- 新增的 `@unchecked Sendable` 仅覆盖明确同步边界：`VoiceChatCore.ASRSession`、`LegacyAudioCaptureCallbacks`、`AudioCaptureRunState`、`PCMFrameSourceRelay` 和 `SingleGreenDemo` 的 `CameraSessionPipeline`。这些类型的共享状态由既有锁、串行生命周期或 AVFoundation 回调边界保护；新增类型不得复制该模式而不补充同等理由和测试。
